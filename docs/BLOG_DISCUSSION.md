# Обсуждения блога

Реализация для `/blog/{slug}/`. Требует миграцию `191_blog_comments.sql`.

## Поведение

- Гости и пользователи могут писать несколько сообщений. Имя обязательно, роль необязательна; текст до 2000 символов.
- Корневое сообщение содержит текст и/или оценку 1–5. Ответ содержит текст без оценки. Ответы отображаются одним уровнем с указанием адресата.
- Одна оценка на статью и cookie `fgos_vote_token`, включая отклонённую оценку. Это ограничение браузера, а не подтверждение уникальности человека.
- Новые ветки сверху, ответы по времени. Сервер выводит 20 веток; курсор `comments_before` обеспечивает обычную навигацию без JS и AJAX-подгрузку.
- Тексты, имя и роль проходят YandexGPTModerator в режиме обсуждения. Сбой или неоднозначный результат оставляет сообщение в ручной очереди. Ручное решение имеет приоритет над поздним ответом ИИ.
- Скрытие любого родителя скрывает его потомков без изменения их статусов. Рейтинг учитывает только одобренные корневые сообщения со звёздами.
- Редактирование читателем и уведомления не включены.

## Интерфейсы и эксплуатация

`POST /ajax/submit-blog-comment.php`: `csrf_token`, `publication_id`, `parent_id` (необязательно), `author_name`, `author_role`, `body`, `rating` (пусто либо 1–5), `request_key` (32 hex), honeypot `website`.

Ответ: `success`, `id`, `root_id`, `status`, `visible`, `duplicate`, `message`. Повтор неизменённого запроса с тем же ключом возвращает сохранённую запись. Изменение данных требует нового ключа. При сетевой ошибке форма сохраняет текст и ключ. Повторная оценка даёт 422; превышение лимита — 429.

`GET /ajax/get-blog-comments.php?publication_id=…&before=…`: `success`, безопасно экранированный `html`, курсор `next`, агрегаты `stats`. Публикуются только доступные ветки публичной статьи блога.

Админка: `/admin/reviews/?section=blog`. Доступ и CSRF используют общую защиту админки. Есть фильтры статусов, контекст ответа, одобрение и отклонение.

Лимиты: 10 новых отправок с браузера и 30 с IP за 10 минут. Проверка и расход лимита выполняются под `flock` в `/tmp/blog_rl_*`. Схема рассчитана на текущий один web-контейнер; для нескольких реплик потребуется общее хранилище лимитов. Дубли не расходуют лимит повторно.

Миграция аддитивная: создаёт `blog_comments`; существующие `reviews` и `review_stats` не меняются. Уникальные индексы защищают оценку и идентификатор запроса. Не подключать автоматический посев отзывов к новой таблице.

## SEO

`BlogPosting`, `BreadcrumbList`, опубликованные `Comment` и текстовые `Review`, реальный `AggregateRating`. Один текст с оценкой описан узлом с типами Comment/Review и стабильным ID. Оценки без текста входят только в агрегат. Содержимое обсуждения не меняет дату редакционного обновления статьи.

У каталога есть CollectionPage/ItemList/Blog. Пагинация имеет собственный canonical и номер страницы в title; поиск, фильтры, сортировки и дополнительные страницы обсуждения — `noindex,follow`. Редакционные SEO-переопределения сохраняются для статей и основной страницы каталога. `/blog/` добавлен в sitemap.

[Google не поддерживает Article/BlogPosting как типы review-snippet](https://developers.google.com/search/docs/appearance/structured-data/review-snippet). Семантически правильный рейтинг статьи не гарантирует звёзд или рост позиций.

## Проверка 7 октября 2026

- Изолированная MySQL: 28 проверок, включая миграцию дважды, конкурентные повторы и оценки, конкурентный лимит, ручное решение во время ИИ-проверки, скрытие потомков, валидацию и безопасный HTML/JSON-LD.
- Playwright: 12/12, desktop Chromium и mobile Safari; форма, клавиатура, пагинация с JS и без него, ошибки с сохранением текста, успешная отправка и ожидание модерации, CSRF, закрытые служебные файлы, SEO. Ответы POST в UI-сценариях подменяются для детерминированной проверки интерфейса.
- Отдельная реальная HTTP-проверка локального сервера: гостевой отзыв одобрен настроенным ИИ; ответ пользователя сохранён pending; профильное имя, дубли, вторая оценка, одобрение администратором и скрытие ветки проверены без подмены API. Вход для проверки создан локальной тестовой сессией; процесс логина не тестировался.
- Проверки существующего издателя блога прошли. Регрессия журнала: 4/6; два Safari-теста падают на существующих предупреждениях CSP report-only, а не на ошибке обсуждений.
- На ширине 1280 px обнаружено существующее переполнение общей шапки (scrollWidth 1481), воспроизводится и на каталоге без обсуждения. Новый блок укладывается в viewport, на мобильном переполнения нет.
- Schema.org Validator: каталог, статья, ответы и страница с текстовым Review приняты без ошибок и предупреждений. Проверка относится к коду, не к переиндексации production.
- Google Rich Results: тест кода запущен, но сервис вернул «Something went wrong — Log in and try again». Результат Google не подтверждён; повторить после деплоя через авторизованный Search Console/Rich Results Test.

## Повтор проверок

Для `tests/blog-comments-test.php` предварительно создать отдельную пустую БД с именем `pedagogy_blog_test_…` и выдать локальному пользователю БД доступ; передать это имя через `BLOG_TEST_DB`. Скрипт не использует рабочую БД, но тестовую схему надо удалять после запуска.

```sh
docker exec -e BLOG_TEST_DB=pedagogy_blog_test_example pedagogy_web php tests/blog-comments-test.php
docker exec -e BLOG_UI_TEST=1 pedagogy_web php tests/blog-comments-ui-fixture.php
cd tests/ui
npx playwright test blog-discussion.spec.js --workers=1
# Отдельно: вызывает настроенный ИИ-модератор, только localhost.
BLOG_HTTP_TEST=1 node blog-http.integration.cjs
```

Из корня проекта после UI-проверки:

```sh
docker exec -e BLOG_UI_TEST=1 pedagogy_web php tests/blog-comments-ui-fixture.php --clean
```

При деплое применить миграцию и проверить публичные страницы, форму и админку по процедуре fgos-deploy. Локальные результаты выше не заменяют production-приёмку.
