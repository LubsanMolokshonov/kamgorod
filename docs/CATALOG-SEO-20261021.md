строка или конфликт SEO-поля отменяет всю транзакцию соответствующего раздела.

как исходное обоснование, без обещания роста позиций.

### Конкурсы

Нормализованные выборки реализованы, но **COMPETITION_CATALOG_FACTS_ENABLED=false
по умолчанию**. Пока нет подтвержденной классификации всех действующих карточек,
включение этой настройки на production недопустимо: иначе специализированные выдачи
сократятся до разобранного ассортимента. При выключенной настройке сохраняется
историческая выборка; старый AJAX также использует общий сервис каталога.

В приложении явно подтверждены роли пяти карточек: «Умный малыш», «Мы вместе»,
«Говорим правильно», «Современный урок по ФГОС», «Логопедическая мастерская».
Остальные **355 карточек требуют классификации**. Предметы, ступени, требования,
календарь и утвержденные положения нельзя достоверно восстановить из общего шаблона.

На QA с включенной новой выборкой применяются общий хаб и методическая ветвь логопедии;
**84 из 86 категорий откладываются**. При выключенном флаге импорт откладывает все
85 специализированных категорий. Непустая новая выборка сама по себе недостаточна:
должны быть разобраны все исторические кандидаты категории, включая исключенные.
Флаг не включает индексацию автоматически — нужны согласованные SEO-поля и intro.

На всех карточках шаблон выводит реальные участника, номинации и стоимость,
действующий путь оформления и серверный текст условий с PDF из той же функции.
Скользящий дедлайн, неподтвержденный учебный год, общие цели и универсальные критерии
скрыты. Дополнительное содержание появляется только из проверенных `content_json`.
Это не означает редакционное утверждение индивидуальных положений всех 360 конкурсов.

Текущий выбор места заявителем сохранен. Новая загрузка и экспертная оценка не
добавлялись. Публичные обещания приведены к этому процессу. Владелец программы должен
согласовать индивидуальные правила и согласованность с офертой до выпуска контента.

### Отзывы и аналитика

Каталог больше не использует `landing_reviews`, содержащие AI-примеры. Для конкурсов
выводятся только сохраненные `reviews.content_source='user'` со статусом approved;
AI-примеры исключаются также из рейтинга карточки и JSON-LD. Модерация сохранена.

У purchase один отправитель вместо трех. Claim проверяет владельца, succeeded и CSRF,
выдает двухминутную аренду; mark требует ее токен. Общий ключ браузера предотвращает
повторный push после сбоя mark. Бесплатная позиция 2+1 имеет цену 0, сохраняются ID,
coupon-маркеры и курсовые цели. Произвольная номинация не уходит в ecommerce.

`metrika_sent_at` означает передачу события в браузерную очередь. Это **не подтверждение
приема Метрикой**. Очистка хранилища браузера, сбой между push и записью ключа,
блокировщик и потеря сети не позволяют обещать exactly-once доставку во внешний счетчик.

## Запуск и откат

Команды импорта по умолчанию выполняют dry-run. Не использовать рабочие credentials
или production-базу для тестов. В текущем workspace QA-контейнеры именуются
`pedagogy_catalog_qa_db` и `pedagogy_catalog_qa_web`, HTTP — `localhost:8093`.
После итоговой проверки оба QA-контейнера остановлены, данные сохранены. Для повторной
проверки запустить сначала `docker start pedagogy_catalog_qa_db`, дождаться готовности
MySQL, затем `docker start pedagogy_catalog_qa_web`.

1. Для новой QA-копии получить публичный снимок скриптом `scripts/seo-catalog-snapshot.php`
   из корня целевой read-only среды. Подготовить файлы через
   `python3 scripts/bootstrap-catalog-qa.py --snapshot <snapshot.json>`.
   Загрузить полученный SQL только в новую пустую базу `catalog_qa` отдельного контейнера.
   Для web использовать auto_prepend из сгенерированного `qa.ini`, создать каталог сессий
   `/tmp/catalog-qa-sessions`, доступный Apache. Запускать Apache непосредственно,
   без штатного entrypoint, запускающего cron.
2. Применить SQL 194, 195, 196. Миграция 194 должна предшествовать новому коду создания
   заявок и любому переименованию. Проверить отсутствие пустых snapshots. На снимке
   413 старых заявок; перед production повторить подсчет. При существенно большем объеме
   спланировать пакетный backfill, а не запускать большой UPDATE без оценки.
3. Подготовить комплект:

```bash
python3 scripts/prepare-catalog-release.py \
  --snapshot editorial/reviews/seo-catalog-20261021/snapshot.json \
  --courses editorial/reviews/seo-catalog-20261021/sources/FGOS_134_SEO_names_NEW.xlsx \
  --competitions 'editorial/reviews/seo-catalog-20261021/sources/ТЗ_конкурсы_реестры URL.xlsx' \
  --brief editorial/reviews/seo-catalog-20261021/sources/ТЗ_конкурсы.docx \
  --output editorial/catalog-20261021
```

4. Проверить и применить курсы в QA:

```bash
docker exec pedagogy_catalog_qa_web php scripts/apply-catalog-release.php --file=editorial/catalog-20261021/package.json --section=courses
docker exec pedagogy_catalog_qa_web php scripts/apply-catalog-release.php --file=editorial/catalog-20261021/package.json --section=courses --apply --environment=local
```

Для конкурсов используется тот же интерфейс с `--section=competitions`. Список
`deferred_categories` — обязательный результат проверки, его нельзя считать выполнением
всего реестра. Для следующей версии классификации добавить `expected_facts` с исходным
состоянием; ручные правки без этого основания не перезаписываются.

5. Интеграционный тест импорта запускать на исходном снимке до применения пакета:

```bash
docker exec pedagogy_catalog_qa_web php tests/catalog-release-test.php
docker exec pedagogy_catalog_qa_web php tests/catalog-purchase-test.php
docker exec pedagogy_catalog_qa_web php tests/catalog-reviews-test.php
docker exec pedagogy_catalog_qa_web php tests/seo-technical-test.php
```

После применения локального пакета:

```bash
docker exec pedagogy_catalog_qa_web php tests/catalog-graph-test.php
cd tests/ui
BASE_URL=http://localhost:8093 npx playwright test catalog-release.spec.js --workers=1
```

Тесты синтетических данных не вызывают платежный API и не отправляют писем. Их
изменения ограничены QA-базой и убираются в finally. До повторного полного теста импорта
примененный демонстрационный пакет нужно откатить.

6. Откат данных: сначала dry-run, затем применение. Он восстанавливает только поля
   пакета, блокирует потерю поздних правок, не меняет snapshots новых заявок:

```bash
docker exec pedagogy_catalog_qa_web php scripts/apply-catalog-release.php --rollback=catalog-20261021
docker exec pedagogy_catalog_qa_web php scripts/apply-catalog-release.php --rollback=catalog-20261021 --apply --environment=local
```

После отката данных отключить новый режим выборки и при необходимости вернуть код.
Колонки snapshots и журнал при откате не удалять: они нужны для истории заявок,
созданных под новым названием. Новые миграции останавливаются при неожиданной ошибке;
проверка фактической структуры перед импортом обязательна.

Production выполняется только по отдельному явному запросу и навыку fgos-deploy,
на сервере **141.105.69.45**. Частичный выпуск не означает приемку отложенных
карточек и категорий или устранение указанного ниже дефекта авторизации.

## Отдельная находка безопасности

При read-only security review найден существовавший до этого diff путь в
`ajax/save-registration.php`: обработчик находит пользователя по введенному email,
а затем устанавливает его `user_id` в сессию без подтверждения владения адресом.
Собственный CSRF не предотвращает такой вход в существующий аккаунт. Добавленный
CSRF закрывает межсайтовую отправку, но не этот самостоятельный дефект.

Это критичный отдельный вопрос перед выпуском: существующий аккаунт должен требовать
уже подтвержденную сессию или magic-link. Нужна проверка всех похожих путей
индивидуальной/групповой регистрации и записи на курс, чтобы исправление одного
обработчика не оставило альтернативный путь. В рамках SEO-комплекта механизм входа
не менялся и заявка против чужого реального аккаунта не отправлялась.
