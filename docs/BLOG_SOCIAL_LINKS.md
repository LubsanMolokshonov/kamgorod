# Короткие ссылки и оформление старых анонсов

Новые Telegram-анонсы используют кнопку «Читать статью на fgos.pro», VK и RSS —
короткий адрес `/s/vk/<id>`. Telegram-кнопка ведёт на `/s/tg/<id>`. Переход возвращает
302 на актуальную опубликованную статью с прежними `utm_source=telegram|vk` и
`utm_campaign=blog`. По ID переживает смену slug; поддерживает объединение статей
через `redirect_to_slug`. Открытого перенаправления на произвольный сайт нет.
Маршрут следует сохранять при откате публикаторов: ссылки уже могут быть в постах.

## Исправление истории

`scripts/update-blog-social-links.php` редактирует существующие посты; новых не создаёт.
Предпросмотр выполняет чтение публичных/API данных и сохраняет защищённые снимки.
Публикаторы и их выключатели эта команда не включает, дневные слоты не расходует.
Весь запуск использует MySQL lock штатного публикатора и отдельный файловый lock.

Сначала один пост:

```sh
php scripts/update-blog-social-links.php --channel=tg --message-id=534 --journal-dir=/var/lib/fgos-social-links
php scripts/update-blog-social-links.php --channel=tg --message-id=534 --journal-dir=/var/lib/fgos-social-links --apply
```

После проверки результата — история конкретного канала:

```sh
php scripts/update-blog-social-links.php --channel=tg --journal-dir=/var/lib/fgos-social-links
php scripts/update-blog-social-links.php --channel=tg --journal-dir=/var/lib/fgos-social-links --apply
php scripts/update-blog-social-links.php --channel=vk --journal-dir=/var/lib/fgos-social-links
php scripts/update-blog-social-links.php --channel=vk --journal-dir=/var/lib/fgos-social-links --apply
```

`--channel=all` обрабатывает оба канала. Без `--message-id` кандидаты объединяются из
подтверждённых отправок БД и доступной истории: публичные страницы Telegram до конца
архива, VK `wall.get` постранично до исчерпания выдачи. Если полный архив недоступен,
это явно отмечается; сохраняется возможность проверить известные ID. При отсутствии
доступа VK выводится число известных записей и код API без токена. OAuth refresh
этой командой не выполняется. `sending/unknown` в журнале доставок блокирует канал
до прежней процедуры сверки: сохранённый payload доставки никогда не переписывается.

Правила преобразования:

- Telegram: одиночное фото, простая подпись и однозначная строка «Читать на сайте».
  Обрабатываются только известные legacy-отправки с сохранённой подписью и без
  поля `reply_markup` в исходном payload. Найденные в публичной истории посты без
  такой записи пропускаются: widget может полностью скрывать inline-клавиатуру,
  отсутствие кнопок в HTML не доказывает их отсутствие в Telegram.
  Сохранённая подпись сравнивается с текущей. Форматированный текст, скрытые ссылки
  и неизвестные существующие кнопки пропускаются, чтобы не потерять содержимое.
  Фото сравнивается по SHA256 байтов публичного превью с разрешённого Telegram CDN;
  меняющаяся подпись CDN URL не считается заменой фотографии.
- VK: заменить только адрес статьи в тексте; сохранить фотографии и их порядок.
  Посты без `can_edit`, репосты, реклама, подписи авторов, особые поля и сложные
  вложения требуют ручной проверки и пропускаются.
- Стандартные UTM сохраняются. Ссылки без меток получают источник канала.
  Любые дополнительные/повторяющиеся параметры или нестандартные UTM не заменяются.
- Перед API повторно читается пост; ручная правка между снимком и применением
  даёт `conflict`. После правки Telegram проверяется возвращённый Message, VK —
  повторное чтение поста. Ответ Telegram API подтверждает переданную клавиатуру;
  публичный widget кнопки не подтверждает. Предпросмотр/HTTP-проверка не доказывает
  отображение кнопки в нативном клиенте: это отдельная визуальная проверка.

## Журнал и восстановление

Обязательное условие: каталог вне docroot, права 0700; JSON и lock — 0600. Журнал
содержит полные снимки до/после и SHA256, атомарно записывается перед изменением.
Не помещать его в Git, в отчёт или публичный каталог. В Docker путь должен иметь
постоянное хранение либо резервную копию на хосте после каждого этапа. Перезапуск
контейнера сохраняет его файловую систему; пересоздание без volume — нет.

Статусы: `planned`, `sending`, `done`, `conflict`, `rejected`, `unknown`. Последний
означает, что результат изменения не подтверждён; пакет останавливается. Повторный
запуск сначала читает текущий пост: точное совпадение с `after` завершает запись без
API. Если совпадения нет, повторной отправки не будет. Для Telegram публичный
снимок может обновляться с задержкой и не показывать клавиатуру даже после
успешной правки. В этом случае запись `done` остаётся в журнале по проверенному
ответу API, повторный запуск пропускает её без утверждения о текущих кнопках.
После `unknown` требуется отдельная сверка: по одной видимой подписи нельзя
подтвердить, что клавиатура сохранилась.

При ручном восстановлении сначала проверить, что текущая версия совпадает с `after`;
затем восстановить `before` штатным методом редактирования этой платформы. При
расхождении сохранить новую редакцию и остановиться. Не удалять и не создавать
пост заново. Исходные `*_blog_deliveries.payload` — история отправки, не журнал правок.

Выход 0 — проверки завершены без операционных ошибок; 2 — частичный результат,
недоступный канал, конфликт или неподтверждённая правка; 1 — ошибка запуска.
Итоговые строки содержат ID/статусы/причины, без исходного текста и секретов.

## Изолированные проверки

```sh
php tests/blog-social-history-test.php
php scripts/update-blog-social-links.php --help
```

Тест использует только встроенные снимки, fake-вызовы и временный каталог; не
подключается к БД, Telegram или VK и удаляет тестовый журнал после выполнения.
