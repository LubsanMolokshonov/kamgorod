# Участник и заявитель: разделение SEO конкурсов

Решение по итогам проверки 21.10.2026. Контекстные тексты и исключение подтверждённых несовместимых ролей реализованы. Массовая классификация и новые индексируемые подборки пока не применены.

## Критерий разделения

Участник — автор конкурсной работы и получатель основного диплома. Заявитель — человек, который оформляет участие и оплачивает заказ. Один педагог может выступать в обеих ролях в разных заявках. Его профессия сама по себе не определяет категорию конкурса.

| Сценарий | Участник | Заявитель | SEO-направление |
| --- | --- | --- | --- |
| Учитель представляет собственную методическую разработку | Учитель | Сам учитель или организатор | Конкурсы для педагогов |
| Воспитатель оформляет рисунок ребёнка | Ребёнок | Воспитатель | Конкурсы для дошкольников, если возраст подтверждён |
| Учитель оформляет работу школьника | Школьник | Учитель | Конкурсы для школьников |
| Преподаватель СПО представляет свою разработку | Преподаватель | Преподаватель или организатор | Педагоги + профессиональная ступень СПО |
| Студент СПО представляет свою работу | Студент | По подтверждённым условиям конкурса | Конкурсы для студентов СПО |
| Совместная работа педагога и детей | Требует уточнения авторов и документов | Взрослый заявитель | Только после подтверждения категорий авторства |

Тип работы, предмет и образовательная ступень — отдельные признаки. Для педагогического конкурса ступень описывает профессиональную область педагога; для детского — ступень участника. Предмет нельзя извлекать из фрагмента названия.

## Структура и тексты

Существующие URL сохраняются:

- `/konkursy/pedagogi/`: H1 «Конкурсы для педагогов». Участие с собственной профессиональной работой; номинации и документы — по конкретному конкурсу.
- `/konkursy/doshkolnikam/`: H1 «Конкурсы для дошкольников». Ребёнок — участник, взрослый — заявитель.
- `/konkursy/shkolnikam/`: H1 «Конкурсы для школьников». Педагог может оформить участие, но это не основание включать конкурс в педагогическую подборку.
- `/konkursy/studentam-spo/`: H1 «Конкурсы для студентов СПО». Не смешивать студентов и преподавателей СПО; возможность самостоятельной заявки совершеннолетнего требует подтверждения условий.

Общий словарь `AUDIENCE_CATEGORY_GENITIVE_MAP` сейчас превращает детские ветки в формулировки о педагогах. Нужен отдельный контекст конкурсов: глобальная замена затронет курсы и вебинары.

Рекомендуемые вводные тексты:

> Педагогам: «Выберите конкурс для собственной профессиональной работы. Доступные номинации и условия оформления указаны в карточке конкурса».

> Детям: «Выберите конкурс для работы ребёнка. Взрослый оформляет заявку, а в данных участника указывается ребёнок».

FAQ, карточка, форма и HTML/PDF положения должны получать один подтверждённый профиль. В педагогических конкурсах убрать универсальное утверждение «заявку на ребёнка оформляет взрослый». Для неразобранных карточек использовать нейтральное разделение участника и заявителя. Не обещать загрузку работы, независимую экспертизу или гарантированный учёт диплома при аттестации.

## Проверенные исходные данные

Прочитаны полные значения `competitions.target_participants` всех 360 карточек: 149 уникальных формулировок.

| Адресат в старом поле | Карточек | Статус |
| --- | ---: | --- |
| Педагогические роли | 276 | Кандидаты; проверить авторство работы |
| Обучающиеся | 81 | Кандидаты; уточнить возраст/ступень, где их нет |
| Смешанные педагог + обучающийся | 2 | ID 8 и 87; уточнить отдельные авторские категории |
| Воспитатели и родители | 1 | ID 534; уточнить, кто автор работы |

ID 387 и 420 нельзя автоматически отнести одновременно к дошкольникам и школьникам по одному слову «дети». Подтверждённые преподавательские примеры — 85 и 385; у 532 явно указан дошкольный возраст 3–7 лет.

Полная очередь с цитатой исходного поля, ID, slug и предварительным статусом находится локально в `editorial/reviews/functional-seo-20261021/role-split-candidates.csv`; частоты формулировок — в `role-split-full-values.csv`. Это проверяемая очередь, а не импорт утверждённых фактов.

## Порядок применения и приёмка

1. Для каждой карточки подтвердить автора, получателя диплома, ступень/возраст, предмет, тип работы и источник решения. Спорные карточки оставить доступными по прямой ссылке и в общем каталоге.
2. Заполнить `competition_catalog_facts` проверенными значениями; согласовать профиль с историческими связями. Сейчас утверждены только пять профилей; включение общего флага преждевременно сократит специализированные подборки.
3. Применить профиль к общей серверной/AJAX-выборке, счётчикам, минимальной цене и текстам. Отдельно проверить педагогическую, детскую, смешанную и неопределённую роли.
4. Проверить непустые подборки, заголовки, FAQ и положения; затем открывать готовые категории для индексирования и sitemap. HOLD-фасеты автоматически не открывать.

Простая авторизация сохраняется по решению владельца. Обязательное ФИО заявителя относится к оформлению заявки и не является подтверждением личности.

## Реализовано 22.10.2026

- В каталоге используются собственные названия участников, H1/Title и вводные тексты конкурсов. Исторические смешанные SEO-тексты и метаданные не подменяют этот контекст. Курсы и вебинары сохраняют прежний словарь.
- Карточка, FAQ и HTML/PDF положения используют один текст роли по подтверждённым facts; для неизвестных и смешанных ролей текст нейтральный.
- При выключенном общем facts-флаге сохраняется исторический каталог, но подтверждённые несовместимые роли исключаются. Из педагогической подборки исключены детские профили; из детских — подтверждённые педагоги. Список, AJAX, счётчики и минимальная цена получают один фильтр CatalogListing. Непроверенные карточки не включаются в новые ветки.
- Флаг полной нормализации не включается до подтверждения оставшихся 355 профилей. Это не завершённая классификация всех конкурсов. Индексирование HOLD и URL не расширяются.
- Групповая форма требует ФИО заявителя. Корзина и платёж используют общий расчёт: скидка группы округляется до рубля, как в форме; копейки распределяются между позициями чека. Две позиции по 149 ₽ дают 268 ₽. Персональные скидки могут дополнительно уменьшить итог, который показывается точно до оплаты.

Регрессионная проверка: tests/competition-role-split-test.php в изолированной catalog_qa, сначала legacy (28 проверок), затем с --normalized (31). Константа конфигурации должна соответствовать аргументу, иначе тест останавливается. В подготовленном QA prepend она управляется QA_COMPETITION_FACTS; запуск normalized: docker exec -e QA_COMPETITION_FACTS=1 -w /var/www/html pedagogy_catalog_qa_web php tests/competition-role-split-test.php --normalized.

Дополнительно: tests/group-pricing-test.php без БД; tests/group-checkout-test.php только catalog_qa, с подменённым платёжным SDK. Новых SQL-миграций в этой правке нет. Откат кода возвращает прежние тексты и округление, не меняя заявки или документы; уже созданные заказы сохраняют зафиксированную сумму.

Предпосылка выпуска: таблица competition_catalog_facts из миграции 195 обязательна и для legacy-исключений. Перед выпуском проверяется её наличие и пять ранее применённых профилей. Не выполнять полную migrate.php ради этой правки: новых миграций она не содержит.
