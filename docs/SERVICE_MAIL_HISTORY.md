# История сервисной почты для поддержки

`ServiceMailHistory` дополняет разбор `support_alerts` перепиской из Mail.ru.
Это источник контекста для агента, не новый канал приёма обращений. Новых алертов,
записей в БД, отправок и фоновых задач нет. Обязательный вызов описан в
[runbook](../.claude/commands/resolve-alerts.md), шаг 3а.

## Подключение

В серверной `/var/www/kamgorod/.env` задать отдельные параметры
`SERVICE_HISTORY_IMAP_ENABLED=0`, `SERVICE_HISTORY_IMAP_HOST=imap.mail.ru`,
`SERVICE_HISTORY_IMAP_PORT=993`, `SERVICE_HISTORY_IMAP_USERNAME` и
`SERVICE_HISTORY_IMAP_PASSWORD`. Последние два значения не хранить в Git,
аргументах CLI, отчётах и локальной конфигурации. Нужен доступ по IMAP и пароль
приложения Mail.ru; TLS и проверка сертификата обязательны.

После размещения кода проверить до включения:

```bash
ssh root@141.105.69.45 'docker exec pedagogy_web php /var/www/html/scripts/service-mail-history.php --probe'
```

`--probe` явно проверяет подключение независимо от флага; возвращает только
количество/названия папок, не читает письма и не подключается к БД. Проверить,
что среди включённых папок есть входящие, отправленные и нужные архивы. Папки
с IMAP-флагами Junk/Trash/Drafts/NoSelect и типовыми русскими/английскими именами
спама, корзины и черновиков исключаются. Пользовательские папки включаются.

После успешного probe установить `SERVICE_HISTORY_IMAP_ENABLED=1` и проверить
реальное обращение командой ниже. При неуспешной приёмке вернуть `0`. Конфигурация
читается новым CLI-процессом, перезапуск web/cron не требуется. Полное выключение
не мешает обычному разбору обращений.

```bash
ssh root@141.105.69.45 'docker exec pedagogy_web php /var/www/html/scripts/service-mail-history.php --alert-id=123'
```

ID заменить фактическим. Команда делает только SELECT адреса из `support_alerts`.
При выключенном флаге БД и IMAP не вызываются. Только адрес алерта; неподтверждённые
алиасы и поиск по имени не поддерживаются. Ошибки возвращаются кодами без текста
исключений и секретов. История выводится в stdout для внутреннего использования;
не перенаправлять её в общие логи и не коммитить.

## Поиск и формат

Поиск без ограничения давности по From/To/Cc с последующей проверкой точного
адреса. Используются EXAMINE, UID SEARCH и FETCH BODY.PEEK. Не вызываются SELECT,
STORE, MOVE, DELETE, EXPUNGE. Вложения не загружаются: BODYSTRUCTURE выбирает
inline text/plain или text/html, пропускает файлы и вложенные message/rfc822.
HTML очищается без браузера, сети и исполнения содержимого.
BODYSTRUCTURE разбирается из исходного IMAP-ответа: токенизатор установленной
Webklex 6.x повреждает структуру Mail.ru с соседними списками и кавычками перед
закрывающей скобкой. Исправление находится в нашем адаптере, vendor не изменяется.

Из каждой папки берутся заголовки не более 200 последних UID (порядок добавления
в папку), затем кандидаты всех папок сортируются по INTERNALDATE. Тела читаются
у 200 последних кандидатов. Достижение лимита всегда означает `partial`, даже
если последняя запись была ровно двухсотой. При импорте/копировании старой почты
UID может не совпасть с хронологией; результат при отсечении также неполон.
В контекст возвращается не более 50 подтверждённых писем от новых к старым.
Нельзя утверждать, что более ранних писем не было, если поиск неполон.

Общий бюджет CLI — 60 секунд через pcntl (есть в Dockerfile проекта), таймаут
отдельной операции — до 10 секунд с учётом остатка бюджета. Без pcntl остаются
проверки дедлайна между операциями и сетевые таймауты; жёсткая граница требует pcntl.
Текст ограничен 12000 символами, до восьми текстовых MIME-частей по 128 КиБ;
усечение отмечается причиной `body_truncated`. Заголовки ограничены 64 КиБ.

JSON содержит `status`, `complete`, `no_matches`, `reasons`, счётчики и `messages`.
У письма: `date` (дата доставки INTERNALDATE), `timestamp`, `direction`, `from`,
`to`, `cc`, `subject`, `text`, `message_id`, `in_reply_to`, `references`,
`project_evidence`, `truncated`, `source` (ящик/папка/UID).

- `ok` — поиск завершён; `no_matches=true` означает отсутствие подтверждённых писем.
- `partial` — часть поиска выполнена, но есть лимит, усечение или ошибка;
  `no_matches=null`, даже если `messages` пуст.
- `unavailable` — ни одна папка не проверена либо нет адреса/доступа/БД.
- `disabled` — интеграция выключена. Для последних двух `no_matches=null`.

Самостоятельные маркеры: домен `fgos.pro` и «ФГОС-Практикум» с вариантами регистра,
пробелов и дефисов. Письма без маркера принимаются только как потомки подтверждённых
писем через In-Reply-To/References. Общий непроверенный предок и одинаковая тема
не подтверждают проект. Дубли удаляются по Message-ID, при его отсутствии — по
адресам/дате/теме/тексту. Связи за пределами лимита не домысливаются.

## Приёмка

```bash
php tests/service-mail-history-test.php
php -l classes/ServiceMailHistory.php
php -l classes/ServiceHistoryImapReader.php
php -l scripts/service-mail-history.php
```

Тесты используют память, фиктивный транспорт и MIME-фикстуры, без рабочей БД,
Mail.ru, отправок и платных AI-вызовов. Реальную цепочку дополнительно сравнить
с почтой: клиент и проект, порядок событий, предыдущие инструкции и обещания.
Проверить сохранение флагов прочитанности, исключение чужого проекта, затем
подготовить ответ в dry-run по runbook. Отправка для приёмки истории не требуется.
Внутренний отчёт фиксирует статус проверки, причины неполноты и ссылки на
повлиявшие письма (дата/папка/UID), без полной выгрузки переписки.
