# Postmypost: RSS для проверки черновиков

URL: https://fgos.pro/blog-rss.php

Это read-only точка входа. Она не вызывает VK/Postmypost API, не пишет в очередь и не запускает генератор статей.
Выгружаются только source=blog/status=published без redirect_to_slug, с существующей локальной JPEG/PNG/WebP-обложкой.
GUID строится из постоянного ID БД, не из slug или даты. Заголовок, анонс и URL соответствуют статье;
без анонса используются первые 300 символов очищенного текста. Enclosure ссылается на существующий файл без изменений.
Статьи со state sent/sending/unknown и прочими состояниями кроме pending для сообщества 200065283 исключены.
В частности, статья 800, подтверждённая администратором как пост https://vk.ru/wall-200065283_538, не импортируется.
Если БД или журнал недоступны, HTTP 503 вместо успешной пустой ленты. Отсутствующая обложка откладывает статью.

Настройка модуля Postmypost: URL выше, 1 день, «Сохранить в черновик», VKontakte, заголовок/описание/изображение,
ссылка в тексте на новой строке. Проверить выбранный аккаунт сообщества. После сохранения проверить первый импорт:
точный текст, ссылка, исходная обложка, отсутствие статьи 800. Повторная проверка не должна создавать новый черновик.

Ограничения: RSS — протокол чтения, а не подтверждение отправки. Факт чтения НЕ помечает статью отправленной.
Стабильный GUID позволяет получателю распознавать повтор, но поведение Postmypost после редактирования, удаления
модуля, повторного подключения или сбоя публикации ещё не подтверждено. Изменение текста и даты не меняет GUID,
однако потребитель может отдельно реагировать на изменённый pubDate/описание.
Лента содержит доступный неопубликованный архив сразу: первый импорт может создать несколько черновиков.
Нативная настройка «1 день» не означает запуск строго в 12:00 Europe/Moscow и не задаёт квоту одной архивной статьи.
Перед включением режима «Опубликовывать» нужно отдельно проверить расписание, подтверждение результата,
исключение ручных постов и восстановление после сбоя. Для исходных строгих требований предпочтительнее API
Postmypost с постоянным журналом и сверкой неопределённых результатов, а не безусловное включение RSS-публикации.
До этого интеграция VK и её timer остаются выключенными. Статус отправки вручную отмечается только после подтверждения
администратором или сверки с сервисом. RSS самостоятельно ничего в VK не публикует.

Проверка: php -d extension=pdo_sqlite tests/blog-rss-test.php
Ссылки item/link содержат ?utm_source=vk&utm_campaign=blog. GUID и URL изображения не меняются.
