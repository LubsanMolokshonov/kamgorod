# Регенерация пользовательских публикаций fgos.pro

Результат — содержательная и аккуратно оформленная версия на прежнем URL
`/publikaciya/<slug>/`. Это не способ «обмануть AI-детектор»: не обещай процент
«человечности» и не подгоняй текст под нестабильный сторонний балл. Убирай признаки
слабого машинного текста через фактическую точность, конкретику, естественную редактуру
и реальную пользу читателю.

## Границы

- Не меняй `id`, `slug`, `user_id`, автора, дату исходной публикации, сертификаты,
  дипломы, оплату и связанные сущности, если пользователь отдельно этого не запросил.
- Не приписывай автору личный опыт, проведённые исследования, результаты апробации,
  цитаты или квалификацию. Нейтральная методическая переработка допустима.
- Сохраняй исходную работу в `content_original`, если поле ещё пустое, и делай
  закрытую резервную копию строки непосредственно перед записью.
- Подготовка и согласование не разрешают commit, push, deploy или изменение production.
  Для production нужно отдельное явное указание пользователя и навык `fgos-deploy`.
- Для новой статьи `/blog/` используй `pedagogical-articles`, а не этот навык.

## Маршрут

1. Прочитай [процесс подготовки](references/preparation.md). По URL или ID установи
   фактическую запись и причину, по которой видимая страница могла не обновиться.
2. Подготовь закрытый комплект, перепиши материал и создай только нужные изображения.
   Для генерации изображений следуй доступному навыку `imagegen`.
3. Проверь текст, источники, HTML, метаданные, desktop/mobile и все изображения.
   Покажи пользователю готовый результат и зафиксируй хеш согласуемого комплекта.
4. Только после явного разрешения на обновление прочитай
   [безопасную замену](references/replacement.md), затем `fgos-deploy/SKILL.md`.
5. После изменения production проведи приёмку на прежнем URL и запиши в отчёт
   ID, URL, хеши, backup, commit и фактически выполненные проверки.

## Массовая работа

Сначала обработай одну репрезентативную статью и уточни правила на реальном результате.
Для серии веди отдельный комплект и отдельное согласование каждой публикации либо
явно зафиксированный пользователем список одобренных ID и хешей. Обрабатывай малыми
пакетами; ошибка одной записи не должна откатывать или повторно менять успешно
проверенные записи. Не превращай разнообразные авторские материалы в один шаблон:
меняй композицию, примеры и визуальный сюжет по теме.
