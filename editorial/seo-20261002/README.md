# Реализация SEO-ТЗ от 20.02.2026

Подготовлено 02.10.2026. Изменения находятся в рабочей копии, без коммита, push и production-деплоя. Production читался через SSH-туннель; данные и файлы на сервере не изменялись. Туннель закрыт. Локальный Docker запущен для проверки; cron в локальном web-контейнере остановлен.

## Что реализовано

- Пять посадочных с точными Title/H1 из Excel: четыре новых маршрута и КПК начальной школы. Публикации: условия, этапы, проверка, форматы, динамическая стоимость/подписка, реальный образец свидетельства, редакция, FAQ, ссылки на форму. Учительские КПК и конкурсы для аттестации используют действующие карточки. Нет гарантии зачёта документа аттестационной комиссией.
- `/zhurnal/` открывает каталог для чтения. Коммерческое размещение вынесено в `/publikaciya-dlya-pedagogov/`; родительская и дочерняя страницы связаны. Функциональные формы и выдача свидетельства по ID сохранены. Убраны противоречивые обещания времени проверки.
- Начальная школа снова является активной педагогической аудиторией; восстановлены предметные подборки конкурсов, олимпиад, вебинаров и курсов. `/nachalnaya-shkola/` — навигация между учительскими и школьными продуктами. Смешанный `/kursy/nachalnaya-shkola/` сохранён: в production есть 60 КПК и 36 программ переподготовки.
- Подготовлен пакет восстановления **шести** конкретных школьных олимпиад из исходного seed, с 60 вопросами. Локально созданы новые ID, старые записи, регистрации и дипломы не переписаны. Архивные 169 ₽, обещание победы и старый учебный год не перенесены. Это подтверждённые шесть продуктов, а не восстановление неизвестных девяти строк отсутствующего реестра.
- Каталоги конкурсов, аудиторий, вебинаров используют серверные карточки и пагинацию; общий размер страницы — 50. На первой странице HTML-ссылки на все страницы. Исправлены фильтры, создававшие несуществующие сочетания предмета и класса, и маршруты КПК с предметом без ступени образования. Неизвестные фасеты дают 404; валидные пустые результаты — noindex.
- Общая политика canonical/sitemap учитывает редакционно выделенные посадочные; sitemap исключает редиректы, пустые/закрытые фасеты. `lastmod` берётся только из подтверждённой даты содержательного изменения. Технические `updated_at` и время генерации больше не выдаются за актуализацию текста.
- Добавлены независимые SEO-поля и редакционные сведения в `/admin/seo.php`, с CSRF, проверкой путей, дат, профилей и источников, историей предыдущих значений. Исходные названия в документах сохраняются. Автор пользовательской публикации не подменяется. Видимые редакционные сведения и Article/Course/LearningResource согласуются.
- Рассмотрены 447 сущностей; для 255 подготовлен пакет безопасных SEO-полей из фактических названий, содержания и публичного авторства. Для 192 неразличимых записей переопределения не подготовлены, они остаются в очереди. Проверены коллизии предлагаемых значений со всем production-обходом; неразличимые значения не подменяются номерами/суффиксами, а уходят в редакционную очередь. У импортера есть проверка исходного хеша, полей, ID/slug, конфликтов и повторного применения.
- Семь предложенных 301 подтверждены полным совпадением текста, названия и автора. Адресный пакет меняет только redirect, сохраняет документы и исходные ID. Локально применились две пары; остальные отсутствуют/отличаются в старой локальной БД. Остальные предложения из Excel не применяются автоматически.
- Исправлены мобильные сетки, ограничения медиа, перенос хлебных крошек, поля формы, размеры кнопок и прокручиваемые таблицы. Отдельный `seo-accessibility.css` подключён с версией; исходники общего CSS-bundle не изменялись, пересборка не нужна.

## Реестр и доказательства

`Реестр решений.xlsx` содержит **все 3 561 исходные строки** пяти листов, без молчаливых исключений: 264 запроса, 2 290 сирот, 51 строка каннибализации, 951 строка метаданных, пять посадочных. Есть HTTP, canonical, индексируемость, входящие HTML-ссылки, глубина, решение, причина, локальный результат и исходная строка. Отдельно сохранены 60 групп запросов и редакционная очередь.

- `production-before/`: 7 310 URL, 2 919 URL sitemap, сетевых ошибок нет. Sitemap на момент чтения уже не содержал HTTP-ошибок, noindex или несовпадающих canonical. Найдено 6 949 пар внутренних ссылок с 404, преимущественно несовместимые фасеты. Это **новый аудит**, не исходные 863 строки специалиста.
- `local-after/`: окончательные результаты и граф обхода без JavaScript. Сводка в `acceptance-summary.json`. Сырые снимки, CSV и скриншоты исключены из Git, но сохранены локально.
- Локальная БД существенно старее production. **523 URL из сирот отвечают 200 на production, но отсутствуют локально**; ещё один локальный источник перенаправлен после подтверждения дубля. Эти 524 строки не объявлены принятыми. 1 766 сирот получили подтверждённую HTML-ссылку с глубиной до трёх переходов.
- 76 оставшихся локальных ссылок с 404 ведут на профили авторов, отсутствующих в локальной БД; один 302 ведёт к авторизованной функции баланса материалов. Они не заменены вымышленными профилями или общими страницами.
- Во всех проверенных ответах обоих обходов у `img` присутствует `alt`. Это проверка наличия атрибута, а не ручная оценка содержательности каждой подписи.

## Что остаётся незавершённым

1. Подтверждённые составители/редакторы, квалификации, источники и даты содержательной актуализации отсутствующих сведений. Поля и шаблоны готовы; выдуманные сведения не внесены.
2. Предметная доработка неоднозначных метаданных и покрытия 264 запросов/51 строки каннибализации. Группы и противоречия разобраны, но все формулировки не вставлялись автоматически: среди них устаревшие годы, обещания бесплатности, смешение КПК/ПП, конкурсов/олимпиад. Отсутствующие содержательные различия не считаются исправленными.
3. Полная проверка на актуальной копии данных: из итогового пакета 255 сущностей локально импортер подтверждает 174, пропускает 73 отсутствующие и восемь с отличающимся исходником. Это ограничение тестовой БД, не разрешение обходить проверки перед production.
4. Оригинальные листы «URL и правила», «Проблемные ссылки» отсутствуют. Нельзя доказать выполнение именно исходных 80 canonical, 113 sitemap, девяти 301 и девяти школьных восстановлений. Есть новый граф и подтверждённые адресные решения.
5. Полный цикл регистрации → оплаты → выдачи документов в изолированной тестовой среде, затем production-проверка после отдельного разрешения на деплой. Реальные платежи и отправки писем не выполнялись.

Поэтому весь SEO-план пока **не принят целиком**. Текущий реестр отмечает 2 102 строки как локально проверенные, семь перенаправлений как требующие итоговой проверки решения и 1 452 как непринятые. Это не количество уникальных задач и не процент готовности проекта.

## Подготовка выпуска и откат

Деплой выполняется только по отдельному запросу пользователя и навыку `.agents/skills/fgos-deploy/SKILL.md`.

1. Сохранить резервную копию затрагиваемых таблиц и предыдущую версию кода. Миграции 187–189 добавляют SEO-таблицы, страхуют состояние активности аудитории и новые связи. Не запускать старые массовые миграции школьных олимпиад.
2. Применить новые миграции штатной процедурой, проверить реальное наличие таблиц и состояние данных. Локальные испытания применяли SQL адресно, без запуска всех исторических миграций.
3. Сначала dry-run пакетов с актуальными данными. Каждый скрипт без `--apply` только проверяет:

```bash
php scripts/seo-apply-package.php --file=editorial/seo-20261002/metadata-package.json
php scripts/seo-apply-redirects.php --file=editorial/seo-20261002/verified-redirects.json
php scripts/seo-restore-school-olympiads.php --file=editorial/seo-20261002/school-olympiads.json
```

После разрешённого выпуска для записи требуется одновременно `--apply --environment=production`. Не игнорировать changed_source/conflicting_override/missing: такие строки разбираются отдельно. Реальные составители и даты вносятся через `/admin/seo.php`, не массовой генерацией.

4. Адресный откат: `php scripts/seo-rollback.php --id=ID_ИСТОРИИ` показывает результат; запись только с `--apply --environment=production`. Проверяется отсутствие более новых правок и совпадение текущих значений. Восстановленные олимпиады только деактивируются, без удаления вопросов/документов; при наличии регистраций автоматический откат блокируется. Аудитория и её новые связи откатываются по `seo_audience_restore_backup`/`seo_primary_olympiad_links` и резервной копии, с проверкой последующих изменений. Код откатывается к сохранённой версии.
5. Повторить production-обход и сценарии документов. Только затем сформировать список конечных URL для переобхода. Никакие сообщения специалисту и отправки в поисковые системы в этой работе не выполнялись.

## Повторение анализа

```bash
python3 scripts/seo-registry-audit.py --registry '/путь/Реестры URL для исполнения ТЗ.xlsx' --base http://localhost:8080 --output editorial/seo-20261002/local-after --workers 5
python3 scripts/seo-prepare-package.py --snapshot editorial/seo-20261002/public-snapshot.json --registry '/путь/Реестры URL для исполнения ТЗ.xlsx' --output editorial/seo-20261002
python3 scripts/seo-build-report.py --directory editorial/seo-20261002
```

Пакет генерации сначала пишет редакционную рабочую книгу; последний шаг собирает полный реестр из обеих сред. Снимок публичных полей создаёт `scripts/seo-public-snapshot.php` в read-only транзакции. Пароли, e-mail пользователей и платёжные данные в него не включаются.

Оставшуюся смету нельзя надёжно вывести из 386–634 часов исходного ТЗ: после устранения повторяющихся шаблонных ошибок остаток состоит главным образом из адресной редакционной проверки и данных, отсутствующих локально. Для оценки использовать непринятые **уникальные URL/группы** в реестре, после получения подтверждённых сведений и актуальной тестовой БД; часы сейчас не выдуманы.
